# 冲突解决策略

两端同时修改同一条记录时，需要冲突解决机制。

## 冲突判定

同一 `(entity_type, record_id)` 收到两个 version 存在交叉的变更。

## 解决策略 (可按实体配置)

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| `last_write_wins` (默认) | 取 `changed_at` 较新者 | 用户画像、设置类 |
| `server_wins` | 以云端版本为准 | 全局字典、系统配置 |
| `school_wins` | 以学校本地版本为准 | 实时业务如考勤 |
| `merge` | 字段级合并 (按字段最后更新时间) | 学生信息、成绩 |
| `manual` | 产生待办，人工审核 | 关键财务数据 |

## 冲突审计

- 所有冲突产生 `ConflictRecord` 记录
- 管理员可在后台查看与回滚
